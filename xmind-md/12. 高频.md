# 12. 高频

## 数组和链表区别

### 存储结构

#### 数组

- 连续的内存空间
#### 链表

- 非连续的内存空间
  - 每个节点存储数据 + 指向下一个节点的指针
### 访问方式

#### 数组

- 直接通过索引找到数据
  - O(1)
#### 链表

- 需要遍历所有节点才能找到目标值
  - O(n)
### 插入和删除

#### 数组

- 需要移动后续所有元素
#### 链表

- 只需修改指针，不需要移动数据
### 内存管理

#### 数组

- 连续分配，大小固定
#### 链表

- 分散分配，大小动态
### 适用场景

#### 数组

- 需要随机访问（索引访问）
- 数据量小、查询快
#### 链表

- 经常插入、删除元素
- 数据量大、需要动态扩展
## HashMap 和 HashTable区别

### 线程安全

#### HashMap

- 非线程安全
#### HashTable

- 线程安全
### 性能

#### HashMap

- 性能更高，无锁竞争
#### HashTable

- 性能较低，每个方法都有 synchronized
  - 锁的是整个 Hashtable 对象
### null值

#### HashMap

- key 和 value 都允许 null
#### HashTable

- 不允许 null
## 树的遍历方式

### 深度优先遍历（DFS - Depth First Search）

#### 特点

- 先沿着一条路径深入到底，再回溯继续遍历其他分支
#### 方式

- 前序遍历（Preorder）
  - 根 → 左 → 右
    - 先访问根节点，再访问左子树，最后访问右子树
- 中序遍历（Inorder）
  - 左 → 根 → 右
    - 先访问左子树，再访问根节点，最后访问右子树
- 后序遍历（Postorder）
  - 左 → 右 → 根
    - 先访问左子树，再访问右子树，最后访问根节点
### 广度优先遍历（BFS - Breadth First Search）

#### 特点

- 按层级遍历，从上到下、从左到右依次访问每个节点
#### 方式

- 层序遍历（Level Order）
  - 按层遍历（第一层 → 第二层 → 第三层...）
  - 需要用队列（Queue）来存储当前层的所有节点
## 动态规划

### 定义

#### 是一种最优子结构和重叠子问题的优化算法

- 将大问题分解成小问题
  - 并用递推（迭代）方式保存子问题的最优解，避免重复计算
### 核心

#### 最优子结构

- 大问题的最优解可以由小问题的最优解推出
#### 重叠子问题

- 用记忆化存储或递推表格优化同一个子问题被多次重复计算
#### 状态转移方程

- 通过递推公式，从已知状态推导未知状态
### 主要思想

#### 把问题分解成多个子问题，保存子问题的最优解，利用状态转移方程求解最终答案

### 具体步骤

#### 定义状态

- 确定 dp[i] 表示的含义
#### 状态转移方程

- 找到 dp[i] 和 dp[i-1]、dp[i-2] 等的关系
#### 初始化

- 根据题目给出基本情况
#### 遍历顺序

- 一般是从小到大递推（有时需要逆向）
#### 返回结果

- 通常是 dp[n]
## Java中CMS

### 定义

#### CMS（Concurrent Mark-Sweep）是一种低停顿的并发垃圾回收器

- 专注于减少老年代的GC停顿时间
### 目标

#### 尽量减少应用程序的stw暂停时间

### 流程

#### 标记-清除

- 初始标记（Stop-The-World）
  - 标记GC Roots 直接可达对象，暂停所有用户线程
    - 时间短
- 并发标记（Concurrent Marking）
  - 从 GC Roots 开始，并发地扫描整个老年代，标记可达对象
    - 不会暂停用户线程，并发进行
- 重新标记（Stop-The-World）
  - 由于并发标记过程中对象可能发生了变动（写屏障），此阶段修正可达对象
    - 需要短暂暂停用户线程，耗时较长
- 并发清除（Concurrent Sweep）
  - 并发地清除不可达对象，回收内存
    - 不会暂停用户线程，与应用程序并行执行
### 优点

#### 低延迟，减少应用停顿时间

#### 并发回收，GC 过程与用户线程并行执行

### 缺点

#### CPU 资源消耗大，GC 线程和用户线程同时执行，可能影响性能

#### 浮动垃圾

- 由于 CMS 在并发阶段不暂停用户线程，可能会有新的垃圾对象产生，导致回收不彻底
#### 碎片化问题

- 回收后内存碎片化
### 调优

#### 设置并发线程数

- -XX:ParallelCMSThreads=N
  - N 设为 CPU 核心数的一半左右
#### 控制触发时机

- -XX:CMSInitiatingOccupancyFraction=70
  - 当老年代使用率达到 70% 时触发
#### 开启碎片整理

- -XX:+UseCMSCompactAtFullCollection
## 设计模式

### 设计模式是面向对象设计中常用的解决方案，能够帮助开发者解决常见的设计问题

### 三大类

#### 创建型模式

- 解决对象创建的问题
- 创建型模式主要关注如何实例化一个对象，并且帮助系统在创建对象时避免复杂的创建过程
- 模式
  - 单例模式 (Singleton Pattern)
    - 确保一个类只有一个实例，并提供全局访问点
  - 工厂方法模式 (Factory Method Pattern)
    - 定义一个创建对象的接口，但由子类决定实例化哪一个类
  - 抽象工厂模式 (Abstract Factory Pattern)
    - 提供一个创建一系列相关或相互依赖对象的接口，而无需指定它们具体的类
  - 建造者模式 (Builder Pattern)
    - 使用多个简单的对象一步步构建成一个复杂的对象
  - 原型模式 (Prototype Pattern)
    - 通过复制现有对象来创建新对象，而不是通过新的实例化
#### 结构型模式

- 解决类和对象的结构问题
- 结构型模式涉及如何将类和对象组合成更大的结构，以便更有效地管理和扩展
- 模式
  - 适配器模式 (Adapter Pattern)
    - 将一个类的接口转换成客户端期望的另一种接口，使得原本接口不兼容的类可以一起工作
  - 桥接模式 (Bridge Pattern)
    - 将抽象部分与实现部分分离，使得二者可以独立地变化
  - 组合模式 (Composite Pattern)
    - 将对象组合成树形结构表示“部分-整体”层次结构，使得客户端可以统一对待单个对象和对象集合
  - 装饰器模式 (Decorator Pattern)
    - 动态地为对象添加额外的功能，而不影响其他对象
  - 外观模式 (Facade Pattern)
    - 提供一个统一的接口，简化系统的复杂性
  - 享元模式 (Flyweight Pattern)
    - 使用共享对象来减少内存使用
  - 代理模式 (Proxy Pattern)
    - 为其他对象提供代理，控制对这个对象的访问
#### 行为型模式

- 解决类和对象之间的交互和职责分配问题
- 行为型模式主要解决对象间的通信和职责分配问题
- 模式
  - 责任链模式 (Chain of Responsibility Pattern)
    - 通过多个处理对象形成链式结构，客户端请求沿着链传递，直到找到合适的处理者
  - 命令模式 (Command Pattern)
    - 将请求封装成对象，允许用户在不同的时间间隔执行、撤销、排队执行
  - 解释器模式 (Interpreter Pattern)
    - 给定一个语言，定义该语言的文法表示，并实现一个解释器，用来解释该语言
  - 迭代器模式 (Iterator Pattern)
    - 提供一种方法，顺序访问集合对象，而不暴露该对象的内部结构
  - 中介者模式 (Mediator Pattern)
    - 定义一个中介对象，封装一组对象之间的交互
  - 备忘录模式 (Memento Pattern)
    - 在不暴露对象实现细节的情况下，捕获对象的内部状态，并在以后恢复该状态
  - 观察者模式 (Observer Pattern)
    - 当一个对象的状态发生变化时，所有依赖于它的对象都会得到通知并自动更新
  - 状态模式 (State Pattern)
    - 允许一个对象在其内部状态变化时改变其行为
  - 策略模式 (Strategy Pattern)
    - 定义一系列算法，并使得它们可以相互替换
  - 模板方法模式 (Template Method Pattern)
    - 定义一个操作的算法框架，并将一些步骤延迟到子类中实现
  - 访问者模式 (Visitor Pattern)
    - 为一个数据结构中的每个元素提供一个操作，允许在不改变元素类的前提下对其进行修改
## Java 的多态性

### 多态性让同一个方法在不同的对象上有不同的表现

### 主要特征

#### 编译时多态性

- 方法重载
  - 在同一个类中，方法名相同，但参数类型、数量或顺序不同
#### 运行时多态性

- 方法重写
  - 子类重写父类的方法，使得子类可以提供不同的实现
#### 接口和多态性

- 一个类可以实现多个接口，而接口的引用可以指向实现该接口的任何对象

## 内存越界

### 定义

#### 程序访问了非法或超出其分配范围的内存区域，这通常会导致程序出现错误、崩溃或不稳定等问题

### 常见的情况

#### 数组越界

- 当你尝试访问数组中不存在的元素时，通常会发生数组越界
- 后果
  - 抛出异常
#### 堆栈溢出（栈越界）

- 栈越界是指程序的栈空间被占满，通常是由于递归调用没有正确的终止条件，导致栈的深度不断增加
- 后果
  - 栈溢出异常
