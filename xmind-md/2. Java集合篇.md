# 2. Java集合篇

## 数组与集合

### 数组与集合区别

#### 数组

- 固定长度的数据结构，一旦创建长度就无法改变。
- 可以包含基本数据类型和对象。
- 可以直接访问元素。
#### 集合

- 动态长度的数据结构，可以根据需要动态增加或减少元素。
- 只能包含对象。
- 需要通过迭代器或其他方法访问元素。
### 集合类

#### Collection

- 表示单列集合，主要用于存储和操作元素的集合。
  - Collection和Collections
    - Collection
      - Java集合框架中的一个接口，它是所有集合类的基础接口。
        - 定义了一组通用的操作和方法，如添加、删除、遍历等，用于操作和管理一组对象。
    - Collections
      - Java提供的一个工具类，位于java.util包中。
        - 提供了一系列静态方法，用于对集合进行操作和算法。包括排序、查找、替换、反转、随机化等等
          - synchronizedList方法可以将List包装成线程安全
            - List<String> synchronizedList = Collections.synchronizedList(arrayList);
          - Collections.synchronizedMap可以将Map包装成线程安全
  - List
    - 有序的，能够精确的控制每个元素的插入位置，用户能根据索引访问List中元素。
      - ArrayList
        - 底层实现：基于动态数组实现
        - 查询效率：支持随机访问，查询效率高。时间复杂度为 O(1)。
        - 空间占用：创建时需要分配一段连续的内存空间，会占用较大的空间。
        - 插入和删除操作：插入或删除需要移动元素，速度较慢。如果操作位置不是列表末尾，可能需要移动大量元素。
        - 扩容机制：当数组容量满时，ArrayList 会将数组扩容到原来容量的 1.5 倍。
          - 计算新容量：通常，新容量为原容量的1.5倍，然后检查是否超过最大容量限制。
            - 之所以扩容是 1.5 倍，是因为可以充分利用移位操作，减少浮点数或者运算时间和运算次数。
              - int newCapacity = oldCapacity + (oldCapacity >> 1);
          - 创建新数组：根据新的容量创建一个更大的数组。
          - 复制元素：将原数组中的元素逐个复制到新数组中。
          - 更新引用：将ArrayList内部指向原数组的引用更新为新数组。
          - 完成扩容：扩容后，新的元素可以继续添加。
        - 高并发下的安全问题
          - 部分值为 null
            - 线程1发现当前 size 是 9，而数组容量是 10，所以不需要扩容。
            - 这时 CPU 让出执行权，线程2进来，发现 size 仍然是 9，数组容量是 10，所以也不需要扩容。
            - 线程1继续执行，将数组下标索引为 9 的位置设置值，但还没有执行 size++。
            - 线程2执行时，再次将数组下标索引为 9 的位置设置了一遍，这样线程1和线程2都执行了 size++，导致 size 被增加了两次，但数组的最后一个位置（索引 10）依然为 null。
          - 索引越界异常
            - 线程1发现当前 size 是 9，数组容量是 10，所以不需要扩容。
            - CPU 让出执行权，线程2进来，发现数组容量为 10，因此也没有扩容。
            - 线程1完成 set 操作后，执行 size++，此时 size 变成 10。
            - 线程2执行时，由于 size 已经是 10，而数组的最大索引为 9，线程2试图将元素添加到下标索引为 10 的位置时，就会发生索引越界异常。
          - size 与 add 的数量不符
            - 由于 size++ 不是原子操作，它分为三个步骤：获取 size 的值、将 size 加1、将新的 size 值覆盖原值。
            - 线程1和线程2可能会同时读取到相同的 size 值并分别进行自增，最终导致 size 的更新不准确，造成 size 的值与实际添加的元素数量不符。
      - LinkedList
        - 底层实现：使用双向链表实现。
        - 查询效率：需要从链表头或链表尾开始遍历，时间复杂度为 O(n)。
        - 空间占用：每个节点只需要存储元素和指针，因此相对较小。
        - 插入和删除操作：任意位置插入和删除元素效率较高，只需修改链表的指针，但LinkedList不支持随机访问，所以除了头尾结点外插入和删除的时间复杂度都是O(n)。
  - Set
    - Set 不允许存在重复的元素，Set 中的元素是无序的。 当向Set集合中插入元素时，会先根据元素的 hashCode 值来确定元素的存储位置，然后再通过 equals 方法来判断是否已经存在相同的元素。
      - HashSet
        - 底层实现：使用 HashMap 实现。
        - 唯一性：通过 HashMap 的 Key 保证元素唯一性。
        - 无序性：元素的存储顺序可能会变化，无法保证插入顺序。
      - 有序Set
        - LinkedHashSet
          - 底层实现：继承自 HashSet，使用 LinkedHashMap 实现。
          - 有序性：保持插入顺序。每个元素有两个指针，一个指向上一个元素，一个指向下一个元素。
        - TreeSet
          - 底层实现：通过 TreeMap 实现，元素根据自然顺序或通过指定的比较器进行排序。
          - 有序性：元素会根据比较规则自动排序。
          - 性能：查找、插入和删除操作的时间复杂度为 O(log n)，效率较高。
#### Map

- Map 是一个键值对集合，存储键、值及它们之间的映射。Key 无序且唯一；Value 不要求有序，允许重复。
  - HashMap
    - JDK 1.7 及之前，由数组和链表组成。 JDK 1.8 以后，当链表长度大于阈值（默认为 8）并且数组容量大于64 时，将链表转化为红黑树，减少搜索时间O(log n)。 数组初始容量为16。
      - 底层实现：JDK 1.8 中使用数组 + 链表 + 红黑树实现。
        - Key
          - 一般String 做 Key，因为 String 对象是不可变的，一旦创建就不能被修改，确保了 Key 的稳定性。如果是可变的，会导致 hashCode 和 equals 方法的不一致，影响正确性。
            - 当 key 为null时，直接将 key 的哈希值设为 0，不走 key.hashCode() 方法
        - 重写 equals 和 hashCode
          - 如果 o1.equals(o2)，那么 o1.hashCode() == o2.hashCode() 总是为 true 的。
          - 如果 o1.hashCode() == o2.hashCode()，并不意味着 o1.equals(o2) 会为 true。
        - 红黑树而不是平衡二叉树
          - 红黑树
            - 最长路径不会超过最短路径的 2 倍。优势是牺牲一部分查找性能，换取一部分维持平衡状态的成本。
              - 红黑树优化了链表的查询效率，将复杂度从 O(n) 降低到 O(logn)。
          - 平衡二叉树
            - 任何节点的左右子树的高度差不会超过 1，优势是树的节点是很平均分配的。每次进行插入/删除节点的时候，几乎都会破坏平衡树的第二个规则，进而需要通过左旋和右旋来进行调整。
      - Put 过程
        - 第一步：根据要添加的键的哈希码计算在数组中的位置（索引）。
        - 第二步：检查该位置是否为空（即没有键值对存在）。
          - 如果为空，则直接在该位置创建一个新的 Entry 对象来存储键值对。将要添加的键值对作为该 Entry 的键和值，并保存在数组的对应位置。此时，将 modCount 加 1，以便在进行迭代时发现并发修改。
        - 第三步：如果该位置已经存在其他键值对，检查该位置的第一个键值对的哈希码和键是否与要添加的键值对相同。
          - 如果相同，直接将新的值替换旧的值，完成更新操作。
        - 第四步：如果第一个键值对的哈希码和键不相同，则需要遍历链表或红黑树来查找是否有相同的键：
          - 如果键值对集合是链表/红黑树结构，从链表的头部/红黑树开始逐个比较键的哈希码和 equals() 方法，直到找到相同的键或达到链表/红黑树末尾。
            - 如果找到了相同的键，则使用新的值取代旧的值，即更新键对应的值。
            - 如果没有找到相同的键，则将新的键值对添加到链表的头部/红黑树中。
        - 第五步：检查链表长度是否达到阈值(默认为 8)
          - 数组容量 ≥ 64，则会将链表转换为红黑树，以提高查询效率。 数组容量 < 64，则触发扩容，将数组扩展为原来的 2 倍。
        - 第六步：检查负载因子是否超过阈值(默认为 0.75)
          - 如果键值对的数量（size）与数组的长度的比值大于阈值，则需要进行扩容操作。
            - 0.75 提供了空间和时间复杂度之间的良好平衡。负载因子过低会浪费大量空间，过高则容易产生碰撞，影响性能。
        - 第七步：扩容操作
          - 创建一个新的两倍大小的数组(2 的次幂倍数)。
            - 选择2的n次方原因，只需要判断原来的 hash 值和左移一位后的值（newtable）按位与操作是 0 还是 1。
          - 将旧数组中的键值对重新计算哈希码并分配到新数组中的位置。
            - hash值新增的bit是1还是0，是0的话索引没变，是1的话索引变成“原索引+oldCap”。
          - 更新 HashMap 的数组引用和阈值参数。
      - Get 过程
        - 将 K 传给 get，它调用 hashCode 计算 hash 从而得到 bucket 位置，并进一步调用 equals() 方法确定键值对。
        - 注意点
          - 空指针异常
            - 试用 null 作为键调用 get 方法，而 HashMap 没有被初始化（为 null时），那么会抛出空指针异常。如果 HashMap 已经初始化，使用 null 作为键是允许的，因为 HashMap 支持 null 键。
          - 线程安全
            - 在一个线程中调用 get 方法读取数据，而另一个线程同时修改了结构（如增加或删除元素），可能会导致读取操作得到错误的结果或抛出 ConcurrentModificationException。
      - 线程安全性：HashMap 是非线程安全的。
        - JDK 1.7 使用头插法插入元素，在数组扩容的时候，存在 Entry 链死循环和数据丢失问题。
        - JDK 1.8 在 put 方法存在数据覆盖的问题。使用尾插法避免了环形链表问题。
        - 多线程同时执行 put 操作时，如果计算出来的索引位置相同，会造成前一个 key 被后一个 key 覆盖。
  - LinkedHashMap
    - 继承自 HashMap，底层仍然是基于拉链式散列结构。增加了一条双向链表，使可以保持键值对的插入顺序。同时通过对链表进行相应的操作，实现了访问顺序相关逻辑。
      - 底层实现：继承自 HashMap，增加了双向链表。
      - 有序性：保持插入顺序或访问顺序。
  - TreeMap
    - 底层实现：基于红黑树。
    - 有序性：元素根据自然顺序或通过指定的比较器进行排序。
    - 性能：查找、插入和删除操作的时间复杂度为 O(log n)。
#### 线程安全集合

- java.util
  - List
    - Vector
      - Java 早期提供的线程安全的动态数组，其内部方法基本都经过 synchronized 修饰。
        - 使用对象数组来保存数据，可以自动扩展容量。当数组已满时，会创建新的数组，并拷贝原有的数据。加倍扩容。
  - Map
    - Hashtable
      - 线程安全的哈希表。
        - 底层实现：数组和链表实现。
        - 线程安全：每个方法都使用 synchronized 锁，锁住的是整个 Hashtable 实例对象，性能较差。锁粒度较大。
        - 不支持 null 键和值：与 HashMap 不同，不允许使用 null 键或值。
        - 默认初始容量为 11，每次扩容为原来的 2n + 1。
- java.util.concurrent
  - 并发List
    - CopyOnWriteArrayList
      - ArrayList 的线程安全的变体，其中所有写操作（add、set 等）都通过对底层数组进行全新复制来实现，允许存储 null 元素。
        - 写操作
          - 使用了 ReentrantLock 锁做同步处理，内部拷贝了原数组，并在新数组上进行添加操作，最后将新数组替换掉旧数组。
            - 复制原数组：首先会将原数组拷贝一份，并将新数组的长度增加1，得到一个新的数组。
            - 添加新元素：将新加入的元素放到新数组的最后一个位置。
            - 替换数组引用：然后将新数组的引用替换掉原数组的引用，完成数据更新。
        - 读操作
          - 直接返回结果，操作过程中不需要进行同步。
        - 如果线程A在遍历，线程B在添加元素，可能会导致读取到旧的数据，因为修改是在新数组上进行的，到整个遍历完成后，才会切换到新的数组。
  - 并发 Map
    - ConcurrentHashMap
      - 底层由Node节点数组、链表和红黑树组成
        - 在 JDK 1.7，使用的是 Segment 分段锁。
          - 将数据分成多个段，每个段有自己的锁，进行插入、删除等操作时，只需要获取相应段的锁，而不是整个 Map 的锁，允许多个线程同时访问不同段。
        - 在 JDK 1.8，通过 volatile + CAS 或 synchronized (锁粒度更细，只对特定桶或节点加锁) 来保证线程安全。
          - put 操作
            - 如果 Key 对应的数组元素为 null，则通过 CAS 操作将其设置为当前值。
            - 如果 Key 对应的数组元素（链表表头或树的根元素）不为 null 也就是不为空。
              - 若节点不存在，利用 CAS 设置节点
              - 若节点已存在，则使用 synchronized，然后，遍历桶中的数据，并替换或新增节点到桶中，最后再判断是否需要转为红黑树
            - 如果该 put 操作使得当前链表长度 ≥ 8并数组长度(桶的数量)≥ 64，则将该链表转换为红黑树，提高寻址效率。如果 红黑树的节点数 ≤ 6，会重新退化为链表，节省空间。
    - ConcurrentSkipListMap
      - 实现了一个基于 SkipList（跳表）算法的可排序的并发集合。
        - SkipList 是一种可以在对数预期时间内完成搜索、插入、删除等操作的数据结构，通过维护多个指向其他元素的“跳跃”链接来实现高效查找。
  - 并发 Set
    - ConcurrentSkipListSet
      - 是线程安全的有序集合，底层使用 ConcurrentSkipListMap 实现。
    - CopyOnWriteArraySet
      - 是线程安全的无序集合，可以理解为线程安全的 HashSet。
        - 通过“动态数组（CopyOnWriteArrayList）”实现的，而不是散列表。
  - 并发 Queue
    - ConcurrentLinkedQueue
      - 适用于高并发场景下的队列，它通过无锁的方式（CAS）实现了高并发状态下的高性能。
        - 性能要好于 BlockingQueue
    - BlockingQueue
      - 简化多线程间的数据共享。
        - 读写阻塞等待机制
          - 生产线程较快
            - BlockingQueue 可能会被装满，此时生产线程再试图向 BlockingQueue 队列装入数据时，会被阻塞等待。
          - 如果消费者速度较快
            - BlockingQueue 可能被清空，此时消费线程再试图从 BlockingQueue 读取数据时就会被阻塞。
  - 并发 Deque
    - LinkedBlockingDeque
      - 线程安全的双端队列实现。它的内部使用链表结构，每一个节点都维护了一个前驱节点和一个后驱节点。
        - 没有进行读写锁的分离，因此同一时间只能有一个线程对其进行操作。
    - ConcurrentLinkedDeque
      - 基于链接节点的无限并发链表。可以安全地并发执行插入、删除和访问操作。
        - 适用于许多线程同时访问一个公共集合
#### 遍历方法

- 单列集合
  - for 循环
    - 用带有索引的普通 for 循环来遍历 List
      - for (int i = 0; i < list.size(); i++) { list.get(i) }
        - 可以边遍历边修改元素
          - list.set(i, list.get(i) * 2);
  - for-each 循环
    - 底层基于迭代器。循环访问数组或集合中的元素，简化了迭代过程
      - for (String s : list) { System.out.println(s) }
        - 边遍历并尝试修改元素，会抛出ConcurrentModificationException异常
  - Iterator 迭代器
    - 适用于需要删除元素的情况，避免了 ConcurrentModificationException
      - Iterator<String> iterator = list.iterator(); while(iterator.hasNext()) { iterator.next() }
        - 使用remove方法删除元素
        - 使用set方法修改元素
  - ListIterator 列表迭代器
    - 是 Iterator 的子类，支持双向访问列表，并且可以在迭代过程中修改元素。
      - ListIterator<String> listIterator= list.listIterator(); while(listIterator.hasNext()) { listIterator.next()}
  - forEach
    - Java 8 中引入，可以对集合进行快速遍历，简化了代码，支持传入 Lambda 表达式。
      - list.forEach(element -> System.out.println(element));
  - Stream API
    - Java 8 中引入， Stream API 提供了丰富的函数式操作，可以对集合进行过滤、映射等操作，支持链式调用。
      - list.stream().forEach(element -> System.out.println(element));
- Map
  - for-each 循环和 entrySet() 方法
    - for (Map.Entry<String, Integer> entry : map.entrySet()) { entry.getKey()  entry.getValue());}
  - for-each 循环和 keySet() 方法 (遍历key)
    - for (String key : map.keySet()) { System.out.println("Key: " + key)}
  - Iterator 迭代器
    - Iterator<Entry<String, Integer>> iterator = map.entrySet().iterator();
  - Lambda 表达式和 forEach() 方法
    - map.forEach((key, value) -> System.out.println(key + value));
  - Stream API
    - map.entrySet().stream() .forEach(entry -> System.out.println( entry.getKey() + entry.getValue()));
## 锁 - ConcurrentHashMap

### JDK 1.7 中 Segment分段锁(ReentrantLock)

#### 在 ConcurrentHashMap 中，将整个数据结构分为多个 Segment，每个 Segment 都类似于一个小的 HashMap，每个 Segment 都有自己的锁，不同 Segment 之间的操作互不影响，从而提高并发性能。

### JDK 1.8 CAS 乐观锁 + Synchronized 悲观锁

#### 在 putVal 中，如果计算出来的 hash 槽没有存放元素，就可以直接使用 CAS 来设置值，因为 hash 值经过扰动后，碰撞的几率较低，使用 CAS 可以完成较少自旋的操作。

#### 当发生 hash 碰撞时，说明容量不够或者线程竞争较为激烈，这时使用 synchronized 比 CAS 效率要高，因为碰撞大概率意味着高竞争。

## 哈希冲突

### 链地址法

#### 每个哈希桶（数组的索引位置）对应一个链表（或其他数据结构，如红黑树）。 如果多个键映射到同一个哈希桶，直接将这些元素追加到链表中。

### 开放地址法

#### 如果发生冲突，不使用链表，而是根据某种探测策略寻找新的空闲槽位，直到找到可用位置存储数据。

- 线性探测
  - 依次检查当前索引的下一个位置 (index + 1)，直到找到空槽。
- 二次探测
  - 使用二次方步长寻找新的槽位，避免数据聚集。
- 双重散列
  - 使用两个不同的哈希函数，避免数据聚集问题。
### 再哈希法

#### 当发生冲突时，使用不同的哈希函数再次计算新的哈希值，直到找到空闲槽位。

### 扩容和重新散列

#### 当哈希表的 负载因子（Load Factor = size / capacity） 超过阈值时，自动进行扩容，将原有数据重新映射到更大的数组中。
